## Bug 记录

> 格式:现象 → 根因 → 修在哪 → 验证

### Finding #1 — 官方 `swarmhive-action` 缺 `target` input,多 target Tauri 无法正确发布

- **现象**:计划用官方 `swarm-apps/swarmhive-action` 发布 SwarmDrop(多 target:darwin aarch64/x86_64 + win + linux),但 action.yml 的 inputs 只有 `app/version/version-code/abi/channel/artifacts...`,**没有 `target`**。
- **根因**:CLI `publish tauri` 把 `--target` 统一打到本次所有 artifact 上(`crates/swarmhive-cli/src/commands/publish.rs:120` `f.target = args.target.clone()`),artifact 不从文件名推 target;artifact `target` 默认 `None`(同文件 :473)。server 端 `match_tauri_artifact` 按 `(os,arch)` 匹配,多个 untargeted signed artifact 会撞"恰好一个 untargeted fallback"(`crates/swarmhive-server/src/routes/updates.rs:142`)→ 歧义 → 该平台查更新误返 204。action 无 `target` ⇒ 没法分 target 发,多平台必然全 untargeted。
- **修在哪**:① 本次 dogfood **绕开 action,工作流直接 `npx @swarm-hive/cli publish tauri --target <triple>`**(每 target 一发);② 首跑用 `universal-apple-darwin`(server 对 universal 特例放行任意 darwin arch,`updates.rs:84/130`),单发覆盖 darwin 全 arch,避开多 untargeted 歧义;③ **待修(swarm-apps/swarmhive-action 第 4 仓)**:给 action 加 `target` input 透传 `--target`,否则多平台用户用不了官方 action。
- **验证**:待 workflow 首跑 + curl 端点确认 universal artifact 能被 darwin/aarch64 与 darwin/x86_64 两种 query 命中(200)。

### Finding #2(候选,待确认)— Tauri updater endpoint 走 http(非 https)

- **现象**:SwarmHive 服务器是 `http://47.115.172.218:3030`(无 TLS)。tauri.conf updater endpoint 已切到该 http URL。
- **疑点**:Tauri v2 updater 默认可能拒绝非 https endpoint(需 `dangerousInsecureTransportProtocol` 之类)。curl 验证端点契约不受影响,但真实 Tauri 客户端拉更新可能被 http 拦。
- **状态**:待真客户端验证时确认;curl 200/204 契约先行。

### Finding #3 — CLI 无 `tokens` 子命令,CI 无法铸 scoped token

- **现象**:官方 action README 要求 `token: scoped API token`,但 `swarmhive` CLI 顶层无 `tokens` 命令(只能 web UI 建),CI 场景用户被迫把个人 PAT 塞进 secret。
- **影响**:与"最小权限"相悖;PAT 轮换会让 CI 断。本次 dogfood 先用现有 PAT(加密 secret、自有 server,低风险),记为硬化待办。
- **建议**:CLI 补 `tokens {list,create --permissions,delete}`,让 CI 能自助铸 scoped token。

### Finding #4 — workspace 型 Tauri 应用 bundle 路径不是 `src-tauri/target`(已修)

- **现象**:首跑 CI 构建+签名成功(`swarmdrop.app.tar.gz` + `.sig` 已产出),但 publish 步 `ls src-tauri/target/universal-apple-darwin/release/bundle/macos/*.app.tar.gz: No such file` → exit 1。
- **根因**:SwarmDrop 是 Cargo workspace(根 `Cargo.toml` + `crates/`),`src-tauri` 是成员 → Tauri 产物落到 **workspace 根 `target/`**,不是 `src-tauri/target/`。`swarmhive-cli` skill 的 swarmhive.toml 示例(`src-tauri/target/release/bundle/...`)默认非 workspace,对此型应用是错的。
- **修在哪**:`SwarmDrop/.github/workflows/swarmhive-publish.yml` 的 `BUNDLE` 改 `target/universal-apple-darwin/release/bundle`,dmg 改可选。**产品侧建议**:swarmhive-cli skill / docs 的 artifacts 示例补一句"workspace 型应用产物在仓库根 target",或 `init` 探测 workspace 自动给对路径。
- **验证**:已改,重推触发第二次 CI run。

### Finding #5 — Android release APK 默认禁明文 HTTP,够不到 http dogfood server(待修)

- **现象**:dogfood server 是 `http://47.115.172.218:3030`(无 TLS)。Android 9+ release 默认 `usesCleartextTraffic=false`,拦 `checkUpdateAndroid` fetch 与 APK 下载。
- **修法**:SwarmDrop-RN 已有 `expo-build-properties` 插件 → 在其 `android` 加 `usesCleartextTraffic: true`(prebuild 重生效)。**仅 dogfood**;生产必须 https(同 Tauri Finding #2)。
- **状态**:首个 APK 构建(验证发布链路)先不带 cleartext;§10 真机测试前补 + 重构建。§10 本身**阻塞于无在线 Android 设备**(`adb devices` 空)。
